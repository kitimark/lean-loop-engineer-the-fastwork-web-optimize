# Compose: pick a variant of each part, get a preview link

The console's Compose tab (next to Builds) lists every part of the page, grouped by page region in page order. Each part
is a card with its variants. A variant shows a class badge and a one-line reason; an expandable explanation quotes the
findings ledger (mechanism, visual, chromium, webkit, Lean for and against, lesson, run ids cited). Presets (Default,
v2-proved, strip-demo) fill the picks in one click. The bar at the bottom shows the generated search and the actions
Open, Open compare and Copy link (Copy link is a separate step: it copies the link of the last Open, from your tap). It works on a phone (390 px, over the LAN console) and opens through the owner gate.

## Who decides what

| Piece | Where | Decided by |
|---|---|---|
| Class of a variant, page order, allowed or refused, canonical search | `lean/Fw/Console/Compose.lean` (op `console.compose`, wire `Fw/Wire/Compose.lean`) | Lean (`fwcore`) |
| Goldens | `packages/contracts/golden/console/console.compose.jsonl` (generated by `Fw/Ops/Golden.lean`) | Lean |
| Read `part.json`, presets, ledger; attach ledger text to the row indices Lean named; find run ids | `apps/console-api/src/preview/compose.ts` | glue (TS stand-ins, see below) |
| Route `GET /api/compose[?pick=part:variant,...]`, `GET /api/compose/decision` | same file, mounted in `preview/routes.ts` | glue |
| Open, reuse or start the preview, the link | `POST /api/builds/open` with `{search, arm}` (`console.buildsOpen`) | Lean |
| Cards, picker, bar | `apps/console-web/src/Compose.tsx`, `composeOpen.ts` | rendering only |

## Classes (Lean `Cls`, first match wins)

| Class | Meaning | Link |
|---|---|---|
| original | the faithful variant (kind `faithful`) | allowed |
| refuted | a live ledger row for this variant has status `refuted` (a superseded row is not live) | refused, reason names the finding |
| proved | in the `v2-proved` preset, same look | allowed |
| look-change | the part's `provenance.limit` starts with `look change` | allowed |
| ledger-proved | one or more rows speak of it and every one has status `proved`; the gate has not admitted it to `v2-proved` ("proved in the ledger, not yet admitted to v2-proved by the gate") | allowed |
| measured | a row with a verdict, not all `proved`, not admitted ("not in v2-proved yet (the gate has not admitted it)") | allowed |
| unrated | no ledger row speaks of it | allowed |

A ledger row speaks of a variant (`matchRow`) when: its `flag` is `part:variant` (a row with a flag speaks of nothing else);
or, with no flag, one of four rules holds. Rules 1 to 3 need the row's `part` text to name the part (the text before its first
`(`, or a parenthesis that opens with `+`): (1) the candidate has the word `part:variant`, (2) the candidate starts with the
variant name, (3) the candidate puts the variant in backticks. Rule 4 needs no part name: the row's exact `part` and
`candidate` text is a pair `explicitKeys` names for the variant (the preset link table, plus the extras below).

Extra pairs in `explicitKeys` (the ledger has no `flag` field on them yet; giving rows one is a follow-up for the ledger
owner): `hero.countdown:hidden-pause` gets the `hero.countdown / morph.countdown` hidden-skip row;
`morph.columns:hidden-pause` gets row 19 (`morph.columns`, "columns as a still picture while the menu is closed ...") and
row 41 (`engine.scene`, "hidden pause of compositor marquees (morph.columns ...)"); `morph.countdown:hidden-pause` gets
row 43 (`engine.scene`, "morph.countdown hidden: keep the spring integrating ..."). Checked against the real registry and
ledger: `morph.columns:hidden-pause` was the only unrated variant, and now is `measured` (row 19 is `partly-proved`).

## Superseded rows

A ledger row may carry `supersededBy: <row id>`: the `id` of the later row that fixed or replaced it. Identity, not
inference: Compose reads only that field. A superseded row counts for no class and never refutes (`classOf` is `classBy`
over the live rows); the row it names joins the variant's rows by its `id` (`varRows`), whether or not its text matches
the variant, and the card still lists the superseded row with its own words. A `supersededBy` that names no row's `id`,
or is not a string, makes `console.compose` fail with the reason (`supersedeErrors`); it is never ignored.

Rows marked (task compose-superseded-rows):

| Row | supersededBy | Reason |
|---|---|---|
| `hero.exit.scoped.falsified` (refuted) | `hero.exit.scoped.inline` | the inline reader writes fixed the stale WebKit style cache this row found (its `next`: fResult model-bug cleared) |
| `hero.exit.scoped` (partly-proved) | `hero.exit.scoped.inline` | it records the register-only code that row `hero.exit.scoped.falsified` refuted; the flag's code and proof are now the inline row's, the row the preset link table names for `hero.exit:scoped` |

With these, `hero.exit:scoped` shows `ledger-proved` ("proved in the ledger, not yet admitted to v2-proved by the gate"), not
`refuted`. It is still not in `v2-proved`: the mac-webkit morph cell fails (task trajectory-close-start).

Presets: an entry `variant@impl` whose impl is not the site default (`mui`) refuses the preset button (the composer has no
impl pick, so its link would open the default impl). `implReasons` decides; the golden has a `plain-impl` preset.

A refused combination has no link. A combination is refused for an unknown part or variant, a
refuted pick, or a `requires` or `conflicts` violation of the site registry (`BuildsOpen.validate`, the proved mirror of
`apps/site/src/registry/resolve.ts`). Coupled groups and page-level parts only add notes.

## Proved

`decide_link`, `refused_no_link`, `link_iff` (a link exists exactly when no reason does), `link_resolves` (an allowed link
validates `.ok`), `link_no_refuted`, `link_known_picks`, `classOf_*` (each class and its precedence, `ledgerProved` included), `classOf_superseded_never_refutes`, `classOf_superseding` and `classOf_superseded_cons` (a superseded row changes no class), `classOf_no_superseded` and `varRows_no_superseded` (with no `supersededBy` the classes and rows are the old ones), `varRows_superseded_by` (in a ledger with no error the superseding row is among the variant's rows), `supersedeErrors_nil_iff` (no error exactly when every `supersededBy` names an `id`), `implReasons_nil_of_no_impl`, `entries_inj` and
`search_entries_inj` (two combinations with the same entries pick the same variant of every part), `ordered_nodup`.

## Stale replies

The page tags each `/api/compose` reply with the query it answers (`ans.q`), drops replies of older requests (`newestWins`),
and while the shown reply is not for the current picks it says "updating…", hides the old link, and disables Open, Open
compare and Copy link (`answersNow`). Copy failure shows "Copy failed: long-press the link below" with the link as
selectable text. Tests: `apps/console-web/test/compose.test.tsx` (static render and the pure helpers; the repo has no DOM
test library).

## Accepted limits

- Matching ledger rows to variants is text matching on the candidate (flag first). A row that names neither stays under the
  part's "other findings".
- `supersededBy` resolves to the first row with that `id`; the ledger's ids are unique today, but uniqueness is not checked here.
- The look-change list is not on `main`; Lean reads the `limit` text of the variants.
- The text-to-entries round trip of `render` is not proved; goldens and `apps/console-api/test/compose.test.ts` cover it.
- TS stand-ins to move into Lean later: attaching ledger text by index, the run-id regex (10 to 12 digits), the polling loop
  of `openSearch` (same as the Builds tab).

## Use

Console, tab Compose, pick variants, Open. From a script: `curl -s 'http://127.0.0.1:<port>/api/compose/decision?pick=hero.countdown:strip'`.
Tests: `pnpm --filter @fw/console-api test`, `pnpm --filter @fw/console-web test`, `sh lean/scripts/check.sh`.
