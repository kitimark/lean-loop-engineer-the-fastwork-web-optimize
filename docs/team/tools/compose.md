# Compose: pick a variant of each part, get a preview link

The console's Compose tab (next to Builds) lists every part of the page, grouped by page region in page order. Each part
is a card with its variants. A variant shows a class badge and a one-line reason; an expandable explanation quotes the
findings ledger (mechanism, visual, chromium, webkit, Lean for and against, lesson, run ids cited). Presets (Default,
v2-proved, strip-demo) fill the picks in one click. The bar at the bottom shows the generated search and the actions
Open, Open compare and Copy link. It works on a phone (390 px, over the LAN console) and opens through the owner gate.

## Who decides what

| Piece | Where | Decided by |
|---|---|---|
| Class of a variant, page order, allowed or refused, canonical search | `lean/Fw/Console/Compose.lean` (op `console.compose`, wire `Fw/Wire/Compose.lean`) | Lean (`fwcore`) |
| Goldens | `packages/contracts/golden/console/console.compose.jsonl` (generated by `Fw/Ops/Golden.lean`) | Lean |
| Read `part.json`, presets, ledger; attach ledger text to the row indices Lean named; find run ids | `apps/console-api/src/preview/compose.ts` | glue (TS stand-ins, see below) |
| Route `GET /api/compose[?pick=part:variant,...]`, `GET /api/compose/decision` | same file, mounted in `preview/routes.ts` | glue |
| Open, reuse or start the preview, the link | `POST /api/builds/open` with `{search, arm}` (`console.buildsOpen`) | Lean |
| Cards, picker, bar | `apps/console-web/src/Compose.tsx`, `composeOpen.ts` | rendering only |

## Classes (Lean `Cls`, first match wins)

| Class | Meaning | Link |
|---|---|---|
| original | the faithful variant (kind `faithful`) | allowed |
| refuted | a ledger row for this variant has status `refuted` | refused, reason names the finding |
| proved | in the `v2-proved` preset, same look | allowed |
| look-change | the part's `provenance.limit` starts with `look change` | allowed |
| measured | a ledger row with a verdict, not admitted | allowed |
| unrated | no ledger row speaks of it | allowed |

A ledger row speaks of a variant when its `flag` is `part:variant`, or its candidate quotes the variant in backticks and
names the part (`matchRow`). A refused combination has no link. A combination is refused for an unknown part or variant, a
refuted pick, or a `requires` or `conflicts` violation of the site registry (`BuildsOpen.validate`, the proved mirror of
`apps/site/src/registry/resolve.ts`). Coupled groups and page-level parts only add notes.

## Proved

`decide_link`, `refused_no_link`, `link_iff` (a link exists exactly when no reason does), `link_resolves` (an allowed link
validates `.ok`), `link_no_refuted`, `link_known_picks`, `classOf_*` (each class and its precedence), `entries_inj` and
`search_entries_inj` (two combinations with the same entries pick the same variant of every part), `ordered_nodup`.

## Accepted limits

- Matching ledger rows to variants is text matching on the candidate (flag first). A row that names neither stays under the
  part's "other findings".
- The look-change list is not on `main`; Lean reads the `limit` text of the variants.
- The text-to-entries round trip of `render` is not proved; goldens and `apps/console-api/test/compose.test.ts` cover it.
- TS stand-ins to move into Lean later: attaching ledger text by index, the run-id regex (10 to 12 digits), the polling loop
  of `openSearch` (same as the Builds tab).

## Use

Console, tab Compose, pick variants, Open. From a script: `curl -s 'http://127.0.0.1:<port>/api/compose/decision?pick=hero.countdown:strip'`.
Tests: `pnpm --filter @fw/console-api test`, `pnpm --filter @fw/console-web test`, `sh lean/scripts/check.sh`.
