## The rule (CONFIRMED by source, proved in Lean)

A node with no box in the band is not a consumer and is not compared. The identity is the engine's own answer,
`getClientRects().length > 0`:

- Chromium: `Element::getClientRects` returns no quads for a node without a layout object, so a `display: none` node gives an
  empty list (third_party/blink/renderer/core/dom/element.cc:3409-3413, 3445-3453, 3496-3513@f842f52).
- WebKit: `Element::getClientRects` returns the empty list when `renderer()` is null
  (Source/WebCore/dom/Element.cpp:2041-2065, 1866-1875@862f17dcae0aace47ea0ec16e209d960abfd553c).
- Here the hidden nodes are `.orbit` at width <= 600 (apps/site/src/parts/hero.orbit/orbit.module.css:56-60) and `.deck` above
  600 (apps/site/src/parts/hero.deck/deck.module.css:8-16). The run-1 box bits match: orbit has no box at 390, deck none at 640 and up.

`lean/Fw/Gate/Consumer.lean`: `comparedAt` is the OR of the two arms' box bits, `keptIdx` lists the compared elements,
`skip_hides_nothing` says a skipped element paints identically (nothing) in both arms, and `measured_skipped` checks all 105 units of run
40156078840. Golden `packages/contracts/golden/gate/consumer.jsonl` (8 cases) is replayed by
`packages/gate-breakpoints/test/consumer.test.mjs`. A rendered node is always compared. A node rendered in only one arm is compared on its computed values; the box bits
themselves are not compared (0 such mismatches in runs 40668662980 and 40674554372). An element missing from the DOM in
one arm fails on count.

## The probe and reducer

- `kit.mjs` `boxesOf` records `getClientRects().length > 0` per element per node id at every hero read (`boxes: true` in
  `run.mjs`); `consumer.mjs` is the twin of `keptIdx` and `reduce.mjs` filters the hero rows with it before judging.
- `judgedEqual`: a rest row whose arms read different `scrollY` is skipped (`skip:noSample`), per
  `Fw.Parts.HeroExitScrollOffset.judgedEqual`, replaying `hero-exit-offset.jsonl`.

## Gen.merge: newest run wins (policy change)

The stored failing rows of run 40156078840 kept the cell failed (`tcell`: an own-flag fail comes first). `Gen.merge` replaced a
row only of the same run. It now also replaces a row of the same flags, engine and walk from an older run
(`Fw.Preset.Gen.replaces`; theorems `merge_new_mem`, `merge_older_gone`, `merge_keeps`, `replaces_other_flags`; guards). Rows of other flags
or engines stay. This is a policy change for the lead to review. The stored file was regenerated by `Gen.record`, never edited by hand.

## Limits and lessons
- `display: contents` also has empty client rects (Chromium element.cc:3409-3413@f842f52, WebKit Element.cpp:1869@862f17d)
  while its descendants paint and inherit from it, so "no box paints nothing" does not hold there; no hero registry node is
  `display: contents` today.

- The `debug=nav-transition` recorder is a passive page recorder; it is the only key that starts the macOS leg on a push (Lean
  `Fw.Ci.Trigger.appleRuns`), so the mac result rests on a run that carries it. Chromium rests on one run.
- `proofs` (ledger row n 6) is open and out of the unit.
- Lesson: judge a consumer by the engine's own box answer, not by a CSS guess. A lane with `no verdict` on a walk the flag does not touch is retried once, not patched.
