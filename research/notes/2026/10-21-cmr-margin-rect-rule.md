Question: can the gate stop failing the commission margin on a stale `getComputedStyle` read (a used auto margin inside a
skipped `content-visibility:auto` subtree reading `0px` or an old value) without skipping, scrolling or excusing anything,
using the premise `cv.margin-typed-om` (the Typed OM keeps the computed value in a skipped subtree)?

Unit of decision: one margin longhand cell of one node at one stop. Shorthands, block-axis margins, width, height and
inset are follow-ups. Final design round of task commission-margin-recur (split: cmr-margin-typed-om, this task, cmr-strut-asym).

## Rule (CONFIRMED, proved in Lean: `lean/Fw/Gate/MarginRule.lean`, wired in `lean/Fw/Gate/Items.lean`)

For a longhand k in margin-left, margin-right, margin-inline-start, margin-inline-end of a node, let nfO and nfR be the
Typed OM verdicts of the two arms (the value is not a px `CSSUnitValue`: `auto` or a percentage), `style` the old
comparison and `rect` the node's rect cell (its box items, `Fw.Gate.rectCell`).

| nfO | nfR | rect cell | cell of k |
|---|---|---|---|
| fixed or fixed | any | any | style (T1, `marginStatus_fixed`) |
| non-fixed | non-fixed | none (node has no box item) | style (`marginStatus_no_rect`) |
| non-fixed | non-fixed | equal or differ | the rect cell (T2, `marginStatus_fail_iff`) |

- T1: either arm fixed gives today's cell. T2: with both non-fixed, the cell fails iff the rect cell fails.
- T3: a failing rect cell is never passed: the node's box items stay in the part (`marginStatus_never_pass_over_failing_rect`,
  `Fw.Gate.partVerdict_fail_of_box`) and a decided cell is never pass where the rect fails (`marginStatus_decided_not_pass`).
- No new outcome kind and no "excused" count: the result is the style status or the rect status (`marginStatus_cases`).
- It sits in `itemAt` (`styleItem`), so the sweep hysteresis comparison (`gate.stale`) uses the same cell.
- Goldens: `packages/contracts/golden/gate/literal.jsonl`, 16 cases over (nfO, nfR) x (style equal, differ) x (rect equal,
  differs) plus one block-axis case, generated by `lean/Fw/Wire/GateGolden.lean` and replayed through fwcore by
  `packages/gate-breakpoints/test/verdict.test.mjs`. The existing goldens are byte-stable (new JSON fields only when set).

## Collector and summary

- `packages/gate-breakpoints/src/page.mjs`: next to the `getComputedStyle` read, `el.computedStyleMap().get(name)` for each
  compared name starting with `margin`; a name whose value is not a px `CSSUnitValue` goes to `item.layoutDep`. Both arms,
  both engines, no scroll, no resize, no flag. A missing `computedStyleMap` or a throw flags nothing.
- `packages/gate-breakpoints/src/summary.mjs` (`rectDecided`): per run and engine, the count of cells Lean decided by rect
  (`marginByRect.cells`) and, for each whose style values differed, the stop, node, key, both style values, Lean's style
  status and the rect verdict (`marginByRect.styleDiffer`). Counting only: Lean's reply carries `byRect` and `styleStatus`.

- The premise page test with the new `skippedAfter == wantSkipped` assertion passed: run 39357755482 (premise-tests).

## Limits (accepted)

- A used-margin difference with equal rects passes (the strut is exactly that case).
- Shorthands are not compared separately; block-axis margins and other layout-dependent properties keep today's read.
- A node with no box item keeps the style cell.
- The Blink trigger of the stale read stays INFERRED (the read path is CONFIRMED in the earlier note).
- Not measured: Safari on the phone or the iOS Simulator; a run where the rect cell fails with fixed style.
