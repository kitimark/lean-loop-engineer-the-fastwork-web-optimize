# dry-land-timing-key: the dry-land timing key carries the selected check set

Follow-up of dry-land-slow (research/notes/2026/11-01-dry-land-slow.md). That note found the `timing.slow` alerts on
`fw land --dry` compared different check sets. This task puts the check set into the key. Timing only: no ceiling, no
load-aware baseline, no speed change, no land-semantics change.

## Rule (Lean, lean/Fw/Obs/Timing.lean)

- `checkSetId ids` = the ids in string order, joined by `+` (`idLe`, `List.mergeSort`).
- `setWork ids = [("checks", checkSetId ids)]`; `landWork width jobs ids built` = set, then the `mods` class, then width.
- Theorems: `checkSetId_perm` (selection order does not change the identity), `landWork_set_ne` (different identity,
  different work, whatever the modules and width), `judgeQ0_other_set` (samples of other sets never change a verdict),
  `judge_new_set_noBaseline` (history of other sets only: `noBaseline`, never `slow`, when no ceiling is breached).
- Guards `setRun true/false`: six 22 s runs of a set without the lake lint, then 33.3 s with it: `slow` when the key
  ignores the set, `noBaseline` when it carries it (the dry-land-slow incident).
- Golden `packages/contracts/golden/obs/timing-set.jsonl` (6 rows, generated by `TimingGolden.lean`, checked by
  `--check` in check.sh).

## Emit (TS)

- `land.ts` collects `dryIds` as the dry land selects checks: `reads-scan`, `lint:<ciPaths|footprint|axioms>`,
  `fwcore-build`, each local gate id. The span `fw land / dry total*` gets `set`; the `land dry*` note and the handoff file
  (`writeHandoff`) carry it to the outer `fw / land dry*` and `fw / slot run land pnpm fw land dry` spans (slot.ts spreads
  `readLakeHandoff`, which now returns `set` too; no slot.ts edit was needed).
- `timing.ts` `spanWork` maps a `set` member to the `checks` work dimension with `checkSetId` (a TS copy of the Lean rule,
  checked against the golden in test/timing-work.test.ts). The `checks` dimension of a polish commit is another tool and
  step, so the two never share a key.
- A dry land that fails before choosing its checks has no `set`; its sample is `unkeyed` (existing rule).

## Accepted limits

- A set with fewer than 5 samples in its window gets no relative verdict (`noBaseline`); history does not carry the dim, so
  windows start empty. A check set that changes every land (a new test id in the selection) never builds a window.
- The set id is the closed vocabulary of check ids; `+` must not appear in an id.
