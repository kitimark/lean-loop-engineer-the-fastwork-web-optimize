# What the Claude arms read before deciding, and a traced retrieval follow-up

**Answer.**

- **They read no source.** In the first run, each of the 42 Haiku and Sonnet agents read only its own chunk file of
  row prompts: 88 `Read` calls, all on the session scratchpad, 0 on the repo (MEASURED). There was also one `wc`
  call and no other tool. Every read came before the answer. The prompt forbade any other file or tool. The only
  project context they had came in without a tool call: CLAUDE.md and MEMORY.md, injected as the `instructions`
  attachment. The clean run had no tools at all (`--tools ""`): one turn per row, bare JSON replies, and none
  names a file.
- **Their reasoning was not recorded.** The logs hold 74 thinking blocks with 0 characters of thinking text. Each
  block keeps only its signature, the encrypted full thinking (MEASURED). The answer schema had no rationale field.
  The API never returns the raw chain of thought, at best a summary (CONFIRMED, docs). So "what they reasoned"
  cannot be recovered from any past run.
- **A traced read-only arm is feasible.** Run `claude -p` with only `Read,Grep,Glob` and `stream-json --verbose`
  output: it logs every tool call and result (CONFIRMED, docs). The read fence has to be the working directory
  itself, because reads inside the working directory need no approval and so allow rules cannot fence them
  (CONFIRMED, docs). The working directory is therefore a fresh tree holding only allowlisted, vocabulary-free files
  at the row's pin. The record of reasoning is then the read sequence plus a required `evidence` field (paths and
  line ranges) in the answer, not thinking text.
- **Jev cannot read files or ask for them.** Its API takes one request with `state` and `questions` and returns
  answers with probabilities. It has no tools, retrieval, turns or rationale (CONFIRMED, docs). The "Jev asks for
  more files" idea works only as two sends driven by our code: step 1 is a `choice` question whose options are
  candidate files plus `none`, and step 2 is the question with the picked file in `state`. A hybrid also works:
  the lines Claude read become Jev's state.
- **A gain is unlikely, but the trace answers the question anyway (INFERRED).** The file-context note found that the
  labels are judgments over the row's own text, and that the files a row names mostly restate its label
  (`research/notes/2026/10-2x-jev-file-context.md:12-22`). The follow-up below is built so that a leak cannot score
  as a gain.

Tables: `results/jev-retrieval-research/tables.md`, generated by `node scripts/jev-trace-forensics.mjs --dir <workflow
transcript dir> --clean results/jev-arms-clean --out results/jev-retrieval-research` (2026-10-22). The script writes
only tool names, normalised path classes, offsets, byte counts, call order and thinking-block shape. It never copies
message, tool-result or thinking text, and it refuses to write output that holds a home path, the session id or an
email (`scripts/jev-trace-forensics.mjs`, `main`).

- **What each read was.** Each agent read one distinct file, its chunk file. The Read tool cut each chunk at 8,000

  an offset, so every agent saw every line before answering (column "agents seeing every line" in `tables.md`: 42 of

- **The prompt rule.** The workflow prompt told each agent to read its chunk file and "Do not use any other tool,
  file, search or prior knowledge of this project" (CONFIRMED, the computed prompt in each log, read as data).
- **Context injected without a tool call.** Every log has `instructions` (CLAUDE.md and MEMORY.md), `environment`,
  `skill_listing`, `session_context` and others (MEASURED, attachment types in `tables.md`). The first run therefore
  carried project context the clean run removed. The arms-clean note measured it at about 14 k to 15 k prompt tokens
  per row against about 1.8 k (`research/notes/2026/10-2x-jev-arms-clean.md:117-118@2e723b9e`, MEASURED there).

## 2. Feasibility of a traced read-only Claude arm

All Claude Code facts below are CONFIRMED from the docs fetched on 2026-10-22, unless tagged otherwise.

| need | how | source |
|---|---|---|
| Only read tools | `--tools "Read,Grep,Glob"`. This restricts the built-in set; `--allowedTools` only pre-approves and does not restrict. | https://code.claude.com/docs/en/cli-reference |
| Record every call | `--output-format stream-json --verbose`: `system/init` (model, tools), each assistant `tool_use` and user `tool_result`, the final `result` with cost, usage and `permission_denials` | https://code.claude.com/docs/en/headless |
| Fence the reads | Read-only tools need no approval inside the working and added directories, so allow rules cannot narrow reads there. Deny rules apply to Grep and Glob only "best-effort". The fence is a cwd holding only allowed files, plus `--restricted` ("confines the built-in file tools to the working directories, loads only managed settings and --settings") or `permissions.blockReadsOutsideWorkingDirectories` | https://code.claude.com/docs/en/permissions ("Read-only tools", "Read and Edit"); cli-reference (`--restricted`, v2.1.248+; installed 2.1.304, MEASURED) |
| Second check | A `PreToolUse` hook gets `tool_name` and `tool_input` and returns `permissionDecision: deny` for any path outside the tree. The script also rejects the row if any `tool_use` path in the stream falls outside the tree. | https://code.claude.com/docs/en/agent-sdk/typescript (hooks); the CLI takes hooks through `--settings` |
| No prompt, no stall | `--permission-mode dontAsk` denies anything that would prompt; `--max-turns`, `--max-budget-usd` | cli-reference, headless |
| No project context | `--system-prompt`, `--setting-sources ""`, `--strict-mcp-config`, `--no-session-persistence`, as in the clean run | `scripts/jev-arms-clean.mjs:10-12@2e723b9e` |
| Thinking text | At best a summary, never the raw reasoning. On Haiku 5.5 and Sonnet 5.5 the default display is `omitted` (empty text, signature only). Claude Code's `showThinkingSummaries` asks for summaries "in interactive sessions". Whether it takes effect under `-p` is INFERRED and needs one probe call per model. | https://platform.claude.com/docs/en/build-with-claude/thinking; https://code.claude.com/docs/en/settings-reference |
| Reasoning record that does not depend on thinking | An answer schema (`--json-schema`) with `evidence: [{path, lines}]` (≤ 4 items), checked against the reads in the stream. An item counts only if the agent read those lines. | cli-reference (`--json-schema`) |

- **Why not the Agent SDK.** It offers the same controls (`tools`, `cwd`, `settingSources: []`, `hooks`,
  `canUseTool`, `maxTurns`, `maxBudgetUsd`, `thinking`; https://code.claude.com/docs/en/agent-sdk/typescript). It is
  needed only if the hook must run in-process. The CLI keeps the clean run's harness and its `redactEnvelope`
  (`scripts/jev-arms-clean.mjs:21@2e723b9e`).
- **Why no Bash and no sandbox.** Deny rules do not cover subprocesses such as `grep -r` (CONFIRMED, permissions
  page, warning under "Read and Edit"). Without the Bash tool there is no subprocess, so the OS sandbox is not
  needed.

**Cost per row (INFERRED, measure in the follow-up).** Measured clean-run cost per row: Haiku $0.0006, Sonnet $0.0102
(`10-2x-jev-arms-clean.md:111-112@2e723b9e`, MEASURED there). A traced row resends a growing context on each turn,
mostly from cache. At ≤ 8 reads, ≤ 32 KiB read and ≤ 10 turns, that is about 10 to 50 times the clean tokens:
Haiku ≤ $0.03 and Sonnet ≤ $0.50 per row worst case, or ≤ $21 for 38 rows on both models. Cap it with
`--max-budget-usd` per call (Haiku 0.05, Sonnet 0.60). The dollar figure is Claude Code's `total_cost_usd`; the real
cost is plan quota, as in the clean run.

## 3. Jev capability

- **The API.** A request is `model`, `state` (string, object or array), `questions` (`noul`, `choice` with ≤ 255
  options, `score` 1-10, `box`) and `assets` (images only). A response is `answers` (choice, confidence,
  probabilities; score, legend) and `usage` (CONFIRMED, https://docs.typesafe.ai/api.md, fetched 2026-10-22). It has
  no tool or function field, no retrieval, no file input, no multi-turn, no rationale or citation output, and no way
  for the model to ask for more input (CONFIRMED by absence on the same page). How Jev reasons inside a call is
  INFERRED and stays a black box.
- **The cookbooks keep control flow in the client.** In "function calling", Jev picks a function and arguments
  through `choice`/`noul`, and the client runs it. "Rerank" scores each query-passage pair as an independent `noul`.
  "Hierarchical classification" chains `choice` calls in a client loop (CONFIRMED, https://docs.typesafe.ai/llms.txt
  cookbook list, fetched 2026-10-22). A "request more files" step is the same pattern: our code asks, Jev picks, and
  our code fetches and asks again.
- **Our client.** It sends exactly one POST of a Lean-built body (`packages/oracle/src/client.ts:86-89@2e723b9e`;
  `bodyText`, `lean/Fw/Oracle/Body.lean:38-42@2e723b9e`). The caps are `stateCap` 32768
  (`lean/Fw/Oracle/Redact.lean:195@2e723b9e`), `bodyCap` 65536 (`lean/Fw/Oracle/Send.lean:24@2e723b9e`), `dailyCap`
  200 (`:9`), `runCap` 60 (`:10`) and a per-run 400,000 estimated input tokens (`:135-136`), all CONFIRMED. A two-step
  arm therefore costs ≤ 2 sends per row and needs no client change.
- **Fit with the docs' warnings.** The docs warn against large state with unrelated content and against "System Two
  tasks" with several layers of indirection (`research/notes/2026/10-18-jev-decision-model.md:56-57@2e723b9e`,
  CONFIRMED there). Step 1 is one judgment over a short list, which fits. Step 2 adds file text to the state, which is
  exactly the warned-against shape, unless the excerpt is small and on topic (INFERRED).
- **Giving Jev "more reasoning".** The API has no effort or reasoning knob (CONFIRMED by absence). The only levers are
  what goes into `state` and the question's `instructions`. The hybrid arm tests the first lever.

## 4. Why the follow-up still has to guard against leaks

The ablation note found that 9 rows name a file holding their label, a decoy label or later triage
(`10-2x-jev-file-context.md:17-20`, MEASURED there). A model that can Grep a tree can find such a file even when the
row does not name it (INFERRED). So the traced tree is not "the repo at the pin". It is the repo at the pin filtered
by the same allowlist and vocabulary rule as `Fw.Oracle.Expand` (`ExpandCfg`, `allowed`, `expand_vocabFree`; designed
in `10-2x-jev-file-context.md:121-137`, built by jev-file-context-ablation). The tree has no `.git`, so history
cannot leak.

- No runs and no sends (accepted limit). Every cost and gain figure in sections 2 and 5 is INFERRED.
- The logs were read as data, and only aggregates are written. The prompt rule quoted in section 1 is the one
  sentence the workflow wrote into every computed prompt.
- `showThinkingSummaries` under `-p`, and whether Haiku 5.5 returns summaries at all, are unprobed.
- Jev internals beyond its docs stay INFERRED.
- The design below is a proposal (accepted limit). `Fw.Oracle.Expand` is not yet written in any worktree; the design

**Arms.** All arms run on the same rows.

| arm | what | new calls |
|---|---|---|
| C: clean baseline | Jev, Haiku and Sonnet, existing answers | 0 |
| X: ablation | Jev, Haiku and Sonnet on the `Fw.Oracle.Expand` state, from jev-file-context-ablation | 0 |
| T-haiku, T-sonnet: traced Claude | clean prompt plus "files of the project at the incident's time are in the working directory". Tools Read, Grep and Glob. cwd is the filtered tree at the row pin. The answer schema adds `evidence` | 76 `claude -p` |
| J-pick: Jev requests files | Step 1: a `choice` over the row's kept candidate files (≤ 254) plus `none`. Step 2: the clean question with the picked file's excerpt (≤ 8 KiB) in `state`. A `none` pick replays the clean answer with 0 sends | ≤ 76 Jev sends |
| J-hybrid: Claude's reads to Jev | The clean question with the line ranges T-sonnet read, capped, in `state`. A row with no reads replays C | ≤ 38 Jev sends |

**Lean first: `Fw.Oracle.Retrieve`** (pure; git, the `claude` CLI and the Jev client stay I/O). Goldens go in
`packages/contracts/golden/oracle/retrieve*.jsonl`, and `scripts/jev-trace.mjs` is checked against them.

- `RetrieveCfg`: `allowed` is `Fw.Oracle.Expand`'s (one canonical source; no second allowlist). Plus `maxReads` 8,
  `readBytes` 32768 escaped bytes, `rounds` 2 and `sendsPerRow` 2.
- `tree`: a pin and the path list give the materialised paths. Theorem `tree_allowed`: every path passes `allowed` and
  is vocabulary-free. `decide` shows the ledger, the work graph, `research/` and `docs/` are refused.
- `traceVerdict`: the stream's calls (tool, path, bytes) give `ok | outside | overReads | overBytes`. Theorem
  `traceVerdict_ok`: `ok` means every path is in the tree, there are ≤ `maxReads` calls, and the bytes are ≤
  `readBytes`. Any other verdict drops the row from the arm, counted and not hidden.
- `evidenceValid`: an evidence item counts only if a read in the trace covered its lines. Theorem: valid evidence ⊆
  lines read.
- `pick`: Jev's step-1 probabilities give the argmax option, with ties broken by path order. Theorem `pick_mem`: the
  pick is a candidate or `none`. Theorem `pick_none_noop`: `none` gives a byte-identical clean body, so it replays
  with 0 sends.
- `hybridState`: the read ranges become a capped state field, reusing `capState_of_le`. Theorem: nothing is cut when
  under the cap, and no reads gives the clean body.
- `sendPlan`: rows give runs. Theorem: each run has ≤ `runCap` sends and ≤ 400,000 estimated tokens, and the total
  on any UTC day is ≤ `dailyCap` minus the sends already logged that day.
- `adopt`: paired flips per arm against C and against X on the same model (decided per arm, never pooled). Adopt an
  arm only if it is net +4 against C and net ≥ 0 against X, and has no gain on a row where a file was dropped for
  vocabulary. A hand read then traces each gain to evidence lines that state a fact the row lacks, not to fix-describing
  text. Otherwise record a negative result with its mechanism.

**Budget.**
- Jev: ≤ 114 sends, split into runs of 19 rows (≤ 38 sends, ≤ about 200,000 estimated tokens per run). With the
  ablation's 38 that is ≤ 152 on one day, under `dailyCap` 200. Input is ≤ about 1 M tokens, about $0.04 at $0.042
  per M.
- Claude: 76 traced calls, each capped by `--max-turns 10` and `--max-budget-usd`, at ≤ $21 worst case (INFERRED).
- First, one probe call per model: does `showThinkingSummaries` give thinking text under `-p`? Record yes or no;
  either way the evidence field is the reasoning record.

**Order.** jev-file-context-ablation lands `Fw.Oracle.Expand` first; this task depends on it. Then
`Fw.Oracle.Retrieve` with theorems and goldens, then the T arms, J-hybrid (it needs T-sonnet's reads), then J-pick.
