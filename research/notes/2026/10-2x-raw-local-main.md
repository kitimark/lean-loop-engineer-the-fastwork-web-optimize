# A landed worktree that holds data under .local is never deleted, and device raw lanes go to the main checkout

Answer: disk-gc no longer lists a landed worktree whose `.local/` is not known empty (Lean `local_data_kept`), and the
device CLIs resolve a relative `.local/...` path against the main checkout, so new raw lanes never sit in a worktree.
Incident `inc-raw-in-worktree` (docs/team/incidents/ledger.json).

## What was lost

CONFIRMED (apps/runner/src/disk-gc.ts `deleteItem`, class landed): phone-morph-push, phone-morph-push-r2 and
phone-cols-probe wrote their raw lanes (per-frame timelines) under `<worktree>/.local/phone/...`, which is gitignored.
disk-gc removed each landed worktree with `git worktree remove`; that deletes ignored files as well. The committed
summaries keep per-visit statistics only. The lost raw lanes are not recoverable, and nothing was moved or deleted by this fix.

## The rule

| fact (per landed worktree) | before | now |
|---|---|---|
| `.local/` has 0 entries | candidate | candidate |
| `.local/` has 1 or more entries | candidate | kept, reported (`heldLocal`: path, `.local` bytes, reason `local-nonempty`) |
| `.local/` unread (read error) | candidate | kept, reported as held (bytes counted so far) |

Lean (lean/Fw/Ops/DiskGc.lean): `localClear`, `ruleLandedBase`, `ruleLanded = ruleLandedBase && localClear`, `heldLocal`.
Theorems: `local_data_kept` (`localEntries ≠ some 0` gives `x ∉ select`), `local_nonempty_kept`, `local_unread_kept`
(each OR-branch of "not clear" on its own), `held_local_kept` (a reported worktree is not selected),
`held_local_would_select` (a reported worktree would be selected with an empty `.local`). `rule_landed`,
`land_commit_selects` and `remote_land_selects` carry the new premise `localEntries = some 0`.

TS (apps/runner/src/disk-gc.ts): `localState(wt)` reads the two facts (walk of `.local/`, lstat, no symlink follow;
a missing `.local` is 0 entries; any other read error is `null`); the rest is Lean's reply. Golden rows:
3 new rows in packages/contracts/golden/ops/diskgc.jsonl (generated by lean/scripts/DiskGcGolden.lean), replayed by
`apps/runner/test/disk-gc.test.ts`, plus two temp-tree cases (the raw file survives `--delete`; an empty `.local` does not keep the worktree).

## The device CLIs

`packages/measure-webkit/src/device-raw-dir.mjs`: `rawResolve` is `path.resolve`, except that a relative path whose first
segment is `.local` resolves against `dirname(git rev-parse --path-format=absolute --git-common-dir)`. device-cli,
device-push-cli and device-replay-cli import it as `resolve`, so every `--dir`, `--in`, `--out` and `--source` follows
it. Test: `test/device-raw-dir.test.mjs` (a real worktree: `reduce --dir .local/phone/r1` reads the main checkout's state, no
`.local` appears in the worktree).

## Accepted limits

- `localState` (I/O) and `rawResolve` (path glue) are TS stand-ins. No Lean golden covers the resolver.
- A raw dir passed as an absolute path under a worktree is not redirected; the rule is for the documented relative form.
- The lost lanes are not recoverable; no phone run, no CI push.
